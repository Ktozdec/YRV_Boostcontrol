# YRV_Boostcontrol

Электронный бустконтроллер на **ESP32** для **Daihatsu YRV Turbo (двигатель K3-VET)** плюс
**Android-приложение** для настройки и мониторинга по Bluetooth LE.

Система работает в режиме **пиггибэк** (piggyback): она не заменяет штатный ЭБУ, а ставится
рядом с ним. Контроллер сам управляет соленоидом буст-контроля (давлением наддува) и
аккуратно корректирует сигнал датчика давления (MAP), который видит штатный ЭБУ. Всё
остальное — впрыск, зажигание, диагностика — остаётся за заводским ЭБУ.

> ⚠️ **Дисклеймер.** Проект вмешивается в управление наддувом турбомотора. Неверная
> настройка может привести к передуву, детонации и повреждению двигателя. Используйте на
> свой риск, только на собственном автомобиле и желательно с контролем фактического давления
> и состава смеси. См. раздел [Безопасность](#безопасность).

## Как это работает

Турбонаддувом на этом моторе управляет **вестгейт** (перепускной клапан), которым, в свою
очередь, рулит **электромагнитный соленоид (boost solenoid)**. Чем сильнее «зажат» сигнал на
вестгейт — тем дольше тот остаётся закрытым и тем выше давление наддува.

Контроллер крутит соленоид **ШИМ-сигналом (PWM)** с заполнением (`duty`) 0–100 %:

- **выше duty → сильнее зажат вестгейт → больше буст;**
- **ниже duty → вестгейт открывается раньше → меньше буст.**

Чтобы штатный ЭБУ «не пугался» возросшего давления и не уходил в защиту/срез топлива,
контроллер через ЦАП (MCP4725) **ограничивает сверху сигнал MAP**, который уходит в ЭБУ
(это и есть «обманка по бусту», она же FCD — Fuel Cut Defencer). Фактический буст при этом
контролируется отдельно по реальному датчику.

Итог: вы задаёте целевое давление в приложении, а контроллер сам удерживает его картой +
ПИД-регулятором + помощником раздува, и при этом не даёт заводскому ЭБУ сорваться в защиту.

## Архитектура системы

```
            ┌──────────────────────────────────────────────────────────┐
            │                         ESP32                             │
   MAP ───► │ ADS1115 (АЦП) ─► буст/TPS    карта duty (TPS×RPM, обучение)│
   TPS ───► │                              + ПИД  + раздув (spool)      │ ──PWM──► соленоид ──► вестгейт
            │ тахо (ISR) ─► RPM                                          │
   VSS ───► │ PCNT ─► скорость             обманка MAP ──► MCP4725 (ЦАП) │ ──────► штатный ЭБУ (вход MAP)
            │ K-Line (listen) ─► сниффер                                 │
            │                                                            │
            │ BLE  (YRV_Boost_BLE) ◄──────────► Android-приложение       │
            │ Wi-Fi AP (YRV_Boost_Pro) ─► OTA-обновление прошивки        │
            │ NVS ─► хранение настроек, карты, одометра                  │
            └──────────────────────────────────────────────────────────┘
```

**Что ESP32 читает:**
- **MAP** (давление в коллекторе) и **TPS** (положение дросселя) — через АЦП ADS1115 по I²C;
- **RPM** — по сигналу тахометра (аппаратное прерывание);
- **Скорость (VSS)** — по импульсам датчика скорости (аппаратный счётчик PCNT);
- **K-Line** — пассивно слушает диагностическую шину (сниффер кадров).

**Чем ESP32 управляет:**
- **Соленоид буст-контроля** — ШИМ 30 Гц;
- **Сигнал MAP в ЭБУ** — через ЦАП MCP4725 (ограничение сверху).

## Логика управления наддувом

Итоговый `duty` соленоида складывается из трёх вкладов:

```
duty = БАЗА(карта TPS×RPM)  +  ПИД(правит ошибку буста)  +  РАЗДУВ(открытый duty на спуле)
```

1. **База — 2D-карта duty (TPS × RPM).** Грубая «опорная» подача, своя для каждой комбинации
   нагрузки и оборотов. Карта **самообучается**: установившуюся поправку ПИД она постепенно
   впитывает в себя, так что со временем ПИД почти не приходится работать. У каждой ячейки
   есть метрика доверия (`confidence`), которая показывается в приложении.

2. **ПИД-регулятор.** Доводит реальный буст до цели: реагирует на текущую ошибку (`kP`),
   убирает остаточный недо/передув (`kI`) и гасит резкость подхода (`kD`). Усиление
   подстраивается под обороты (gain scheduling: агрессивнее на спуле, мягче вверху), есть
   упреждение по скорости изменения цели (setpoint feed-forward) и анти-windup.

3. **Раздув (spool assist).** Пока буст далеко ниже цели — контроллер кратко лупит **открытый
   duty до 95 %**, чтобы турбина раскрутилась плотно и быстро, а у самой цели **заранее**
   плавно спускается обратно к ПИД, чтобы не перелететь. Срабатывает один раз на «тычок» газа
   (есть защёлка-латч, не перезапускается на каждом проседании), снова взводится при сбросе газа.

**Важно про потолок duty:** в установившемся режиме duty ограничен **85 %** — выше соленоид
греется и подвисает. 95 % разрешены **только кратковременно** на раздуве.

**Защита (limp).** Пороги жёстко привязаны к цели: **soft = `tB` + 0.15 бар**, **hard = `tB` + 0.20 бар**
(сдвигаются автоматически вслед за целью). Если буст превышает порог:
- **Soft limp** — duty плавно «прижимается» пропорционально превышению (мотор не глохнет, едет мягче);
- **Hard limp** — duty мгновенно в 0 (вестгейт полностью открыт), а также при потере датчиков.

## Сборка и установка

### Android-приложение

Откройте проект в **Android Studio** и соберите модуль `app`, либо из консоли:

```powershell
./gradlew.bat assembleDebug
```

APK появится в `app/build/outputs/apk/debug/`. Приложению нужны разрешения **Bluetooth** и
**геолокация** (Android требует её для BLE-сканирования).

### Прошивка ESP32

Откройте `firmware/boost_controller_refined/boost_controller_refined.ino` в **Arduino IDE**
или **PlatformIO**, выберите свою плату ESP32, установите библиотеки и прошейте.

Библиотеки:
- `Adafruit ADS1X15` — АЦП MAP/TPS;
- `Adafruit MCP4725` — ЦАП обманки буста;
- `Preferences` — энергонезависимая память (NVS);
- `BLEDevice / BLEServer` — Bluetooth LE;
- `WiFi` + `WebServer` + `Update` — OTA.

Подробности по задачам, пинам и таблице NVS — в [firmware/README.md](firmware/README.md).

### Обновление «по воздуху» (OTA)

В приложении: **Настройки → OTA РЕЖИМ**. Контроллер перезагрузится в точку доступа Wi-Fi
**`YRV_Boost_Pro`**. Подключитесь к ней телефоном/ноутбуком, откройте `http://192.168.4.1`,
загрузите `.bin`-файл прошивки.

## Подключение по BLE

1. Включите зажигание (контроллер запитан).
2. Откройте приложение и дайте разрешения Bluetooth/геолокация.
3. Приложение само находит и подключается к **`YRV_Boost_BLE`** (сервис Nordic UART), есть
   автопереподключение.
4. После соединения приложение запрашивает текущие настройки (`GET:SETTINGS`) и заполняет поля.

> Кнопка «СОХРАНИТЬ» в настройках активна только после того, как из ЭБУ пришёл пакет настроек.

## Все настройки: что это и куда крутить

Все параметры меняются на вкладке **Настройки** кнопками `−/＋` или вводом числа, затем
жмёте **СОХРАНИТЬ** (отправляет значения в ЭБУ и пишет их в NVS). Колонка **База** — это
заводское значение по умолчанию из прошивки (блок `ADAPTIVE TUNING` в `.ino`). Диапазоны в
таблицах совпадают с ограничениями в прошивке и приложении.

### Цель и обманка (Target Boost / FCD)

| Параметр | Ключ | База | Диапазон | Что делает |
|---|---|---|---|---|
| Целевой наддув | `tB` | 0.80 бар | 0.30–1.5 | Рабочая цель буста, которую держит регулятор. |
| Лимит FCD | `lB` | 0.95 бар | 0.30–2.0 | Порог, выше которого сигнал MAP в ЭБУ «прижимается». Ставится **выше** целевого буста, чтобы не душить ЭБУ на рабочем давлении, но ниже порога его защиты. |

### Защита от передува (Limp)

Пороги защиты **не настраиваются вручную** — они всегда привязаны к целевому бусту и
автоматически следуют за ним с фиксированным запасом:

| Порог | Значение | Что делает |
|---|---|---|
| **Soft limp** | `tB + 0.15 бар` | Буст выше — duty плавно прижимается (мягкий сброс, мотор продолжает ехать). |
| **Hard limp** | `tB + 0.20 бар` | Буст выше — duty мгновенно в 0 (аварийный сброс). Также срабатывает при потере датчиков. |

Например, при цели `tB = 0.80` → soft limp = 0.95, hard limp = 1.00. Меняете `tB` — пороги
сдвигаются сами. Запас фиксирован в прошивке (`SOFT_LIMP_TARGET_OFFSET` / `HARD_LIMP_TARGET_OFFSET`).

> Раньше soft/hard limp задавались отдельными ползунками. Теперь они производные: ползунки
> `sL`/`hL` в приложении на значение не влияют (ЭБУ пересчитывает пороги от цели).

### ПИД-регулятор и обучение

| Параметр | Ключ | База | Диапазон | Что делает | Куда крутить |
|---|---|---|---|---|---|
| Proportional | `kP` | **20.0** | 0–200 | Сила реакции на текущую ошибку буста. | Вяло догоняет цель → **выше**. Раскачка/перелёт на плато → **ниже**. |
| Integral | `kI` | **14.0** | 0–200 | Убирает стабильный недо/передув (остаточную ошибку). | Стабильно недодувает у цели → **выше**. Медленная раскачка → **ниже**. |
| Derivative | `kD` | **8.0** | 0–50 | Демпфер: гасит скорость подхода к цели. | Дёргается/перелетает → **выше** (осторожно — усиливает шум датчика). |
| Скорость адаптации карты | `lA` | 0.10 | 0.02–0.30 | Как быстро база-карта впитывает поправку ПИД. | Быстрее обучение → **выше**. Спокойнее/стабильнее → **ниже**. |

Кнопки **ОБУЧЕНИЕ** (`lA`=0.30) и **НОРМА** (`lA`=0.10) — быстрые пресеты: разогнать обучение
на время настройки и вернуть спокойный режим для повседневной езды.

### Раздув (Spool)

Идея: пока до цели далеко — держим высокий открытый duty (до 95 %), у цели **заранее** плавно
спускаемся к ПИД. На время раздува интегратор заморожен (нет windup), вверх duty растёт быстро,
вниз — со скоростью `fS`.

| Параметр | Ключ | База | Диапазон | Что делает | Куда крутить |
|---|---|---|---|---|---|
| Полный раздув при дефиците | `bH` | **0.15 бар** | 0.05–1.0 | При каком дефиците (цель − буст) держится максимум 95 %. | Спул вялый → **выше**. Перелетает цель → **ниже**. |
| Конец раздува у таргета | `bL` | **0.03 бар** | 0.0–0.5 | Дефицит, на котором помощник полностью отдаёт управление ПИД. | Обычно не трогать. Раньше отдавать ПИД → **выше**. |
| Скорость спуска duty | `fS` | **150 %/с** | 50–1000 | Как быстро duty падает на подходе к цели. | Перелёт → **выше**. «Клюёт»/недобор у цели → **ниже**. |

Главная «ручка ощущения» здесь — **`bH`**: слишком большой даёт перелёт (поздно спускаемся),
слишком маленький — недодув у самой цели. Подбирается по логам поездки.

### Калибровки датчиков

Это привязка «вольты датчика → физическая величина». Меняйте только если показания не
совпадают с эталоном (буст по механическому манометру, TPS 0 % на отпущенном газе).

| Параметр | Ключ | База | Диапазон | Что делает |
|---|---|---|---|---|
| Ноль MAP | `oP` | 2.56 В | 0.1–4.5 | Напряжение MAP при атмосфере (нулевой буст). Автоматически калибруется при каждом запуске на холостом атмосферном давлении. |
| Множитель MAP | `sP` | 0.55 | 0.1–2.0 | Перевод вольт MAP в бары. Подгоняется так, чтобы буст в приложении сошёлся с манометром. |
| Ноль TPS | `oV` | 0.42 В | 0.1–3.5 | Напряжение TPS на полностью отпущенном газе (0 %). |

### Колёса и датчик скорости (вкладка «Сервис»)

| Параметр | Ключ | База | Диапазон | Что делает |
|---|---|---|---|---|
| Импульсы скорости | `vP` | 5.18 | 1.0–40.0 | Импульсов VSS на оборот колеса. Калибруется по GPS (кнопка «GPS КАЛИБРОВКА»). |
| Зубья ДПКВ / делитель тахо | `pR` | 2.0 | 0.5–8.0 | Импульсов тахосигнала на оборот двигателя (для верного RPM). |
| Ширина шины | `tW` | 195 | 100–300 | Размер резины (через «Шинный калькулятор») для расчёта длины окружности и точной скорости. |
| Профиль шины | `tA` | 55 | 20–100 | то же |
| Диаметр диска | `tR` | 15 | 10–24 | то же |

## Пошаговая настройка с нуля

1. **Калибровка датчиков.** Прогрейте мотор. Убедитесь, что на холостых буст ≈ 0 (ноль MAP
   калибруется автоматически при запуске), а TPS = 0 % на отпущенном газе. При расхождении с
   манометром подправьте `sP` (множитель MAP).
2. **Скорость и обороты.** Откалибруйте `vP` по GPS (вкладка «Сервис»), задайте размер шин.
   Проверьте, что RPM на дисплее совпадает с тахометром — при необходимости поправьте `pR`.
3. **Безопасная цель.** Поставьте консервативный `tB` (например 0.7). Пороги защиты soft/hard
   выставятся сами (0.85 / 0.90) — убедитесь, что защита срабатывает.
4. **Базовый ПИД.** Оставьте заводские `kP`=20 / `kI`=14 / `kD`=8. Включите **ОБУЧЕНИЕ**
   (`lA`=0.30) и поездите в разных режимах — база-карта наберёт форму. Потом верните **НОРМА**.
5. **Доводка ощущения.** По логам поездки правьте раздув (`bH` — главное), затем `kP`/`kD` от
   раскачки на плато. Поднимайте `tB` к рабочей цели **постепенно**, следя за фактическим
   давлением и (желательно) составом смеси.
6. **Сохраните** и при необходимости снимите бэкап через экспорт лога в «Динамике».

## BLE-протокол

ESP32 отдаёт построчный JSON (по `\n`); большие пакеты бьются на чанки по размеру MTU.

**Команды приложение → ESP32:**

| Команда | Действие |
|---|---|
| `GET:SETTINGS` | Запросить текущие настройки. |
| `SET:<key>:<value>` | Изменить параметр (напр. `SET:tB:0.85`, `SET:kP:20.0`). |
| `DUTY:30` | Ручной тест соленоида 0–100 % (**только на стоянке**, скорость < 2). |
| `KREQ:8310F0210C01` | Отправить HEX-запрос в K-Line и получить ответ. |
| `SAVE` | Сохранить настройки и одометр в NVS. |
| `RESET` | Сбросить накопленные мин/макс. |
| `OTA:ON` | Перезагрузиться в OTA-режим (Wi-Fi AP `YRV_Boost_Pro`). |

**Поддерживаемые ключи `SET`:** `tB`, `lB`, `kP`, `kI`, `kD`, `lA`, `bH`, `bL`, `fS`, `oP`,
`sP`, `oV`, `pR`, `vP`, `tW`, `tA`, `tR`, `oD` (одометр), `eH` (моточасы). Ключи `sL`/`hL`
принимаются для совместимости, но значение игнорируется — soft/hard limp производные от `tB`.

**Пакеты ESP32 → приложение:** телеметрия (`T`), настройки (`S`), статистика K-Line (`K`),
ответ K-Line (`KRES`), подтверждения команд (`ack` / `err`).

## Безопасность

- **Это вмешательство в наддув турбомотора.** Передув и детонация ломают двигатель — поднимайте
  цель малыми шагами и контролируйте фактическое давление (механический манометр) и, в идеале,
